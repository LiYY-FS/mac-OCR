## mac-OCR v0.0.11 发布（截图画质修复）

### 问题根源
截图画质模糊**不是压缩问题**（全流程 PNG 无损），而是 `desktopCapturer.getSources()` 的 `thumbnailSize` 参数导致缩小采样：
1. `startScreenCapture` 将 `thumbnailSize` 上限写死为 2560px → 物理分辨率超过 2560 的 Retina/4K/5K 屏被缩小
2. `captureLongSegmentImage` 使用 `display.size`（逻辑点）而非物理像素 → Retina 屏以 1x 采集，分辨率减半

### 修复（commit `3e38afa`）
- `startScreenCapture`：按各显示器 `bounds × scaleFactor` 计算原生物理像素，作为 `thumbnailSize` 请求
- `captureLongSegmentImage`：同上，用 `Math.ceil(size.width * scaleFactor)` 替代逻辑点
- 删除旧 `captureMaxSide = 2560` 硬编码上限
- 下游裁剪/拼接自动适配（crop 用 thumbnailSize/bounds 比例，stitcher 用 naturalWidth），无需改动

- dmg 内 app 二进制：`x86_64 arm64`（Universal）✓
- asar 内 `electron/main.mjs`：`nativeMaxWidth` ×2、`scaleFactor || 1` ×3、`captureMaxSide` ×0 ✓

## 跨平台架构设计（mac → Windows 扩展）
- 产出：`docs/plans/2026-08-25-cross-platform-architecture-design.md`
- 核心结论：现有 `desktopHost` IPC 边界（preload/contextBridge）已跨平台且干净，**渲染进程零改动**；所有平台差异收敛到主进程实现层。
- 方案：新增 `electron/platform/{types.ts,index.ts(工厂),mac/*,win/*}`，共享业务只依赖 `PlatformService` 接口，禁止共享代码直接调 `osascript`/`swiftc`/LaunchAgent。
- OCR 是最大移植成本（Apple Vision 二进制 → Windows 需等价引擎，ADR-3 待用户确认选型）；capture/long/shortcut/tray/持久化可高复用。
- build.sh（hdiutil 专属）拆分为跨平台 `scripts/build-frontend.mjs` + 双 `electron-builder` target（mac dmg / win nsis）+ GitHub Actions 双 runner 矩阵。
- 待确认：Windows OCR 引擎选型、安装包格式（NSIS/Squirrel/MSI）、功能对等范围、CI 环境。
